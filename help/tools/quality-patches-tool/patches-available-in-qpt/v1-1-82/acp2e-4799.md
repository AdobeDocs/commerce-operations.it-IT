# ACP2E-4799: la query GraphQL `requisition_lists` restituisce `total_count` non corretto con impaginazione

La patch ACP2E-4799 risolve il problema per cui la query GraphQL `requisition_lists` restituisce un valore `total_count` errato che riflette solo il numero di elementi nella pagina corrente invece del numero totale di entità dell&#39;elenco di richieste che corrispondono ai criteri della query. Questa patch è disponibile quando è installato [[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) 1.1.82. L’ID della patch è ACP2E-4799. Questo problema è pianificato per essere risolto in Adobe Commerce B2B 1.5.4.

## Prodotti e versioni interessati

**La patch è stata creata per la versione di Adobe Commerce:**

* Adobe Commerce (tutti i metodi di implementazione) B2B 1.5.2-p4

**Compatibile con le versioni di Adobe Commerce:**

* Adobe Commerce (tutti i metodi di implementazione) B2B >=1.5.0 &lt;1.5.3

>[!NOTE]
>
>La patch potrebbe diventare applicabile ad altre versioni con le nuove versioni di [!DNL Quality Patches Tool]. Per verificare se la patch è compatibile con la versione di Adobe Commerce in uso, aggiornare il pacchetto `magento/quality-patches` alla versione più recente e verificare la compatibilità nella pagina [[!DNL Quality Patches Tool]: Cerca patch](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html). Utilizza l’ID patch come parola chiave di ricerca per individuare la patch.

## Problema

Quando i clienti eseguono una query sugli elenchi di richieste di acquisto con impaginazione, il campo `total_count` non riflette il numero completo di elenchi di richieste corrispondenti. Viene invece riportato solo il numero di elementi restituiti per la pagina corrente, rendendo imprecisi i metadati di impaginazione.

<u>Prerequisiti</u>:

Gli elenchi delle richieste di acquisto sono abilitati per Adobe Commerce B2B.

<u>Passaggi da riprodurre</u>:

1. In Amministrazione, vai a **[!UICONTROL Stores]** > **Impostazioni** > **Configurazione**.
1. Nel pannello a sinistra in **Generale**, scegli **Funzioni B2B**.
1. Imposta **[!UICONTROL Enable Requisition List]** su **[!UICONTROL Yes]** e seleziona **[!UICONTROL Save Config]**.
1. Accedi alla vetrina come cliente.
1. Scegliere **[!UICONTROL My Requisition Lists]** e creare sei elenchi di richieste di acquisto.
1. Verificare che il cliente disponga esattamente di sei elenchi di richieste e che ogni nome di elenco contenga `ABC`, in modo che tutti e sei gli elenchi corrispondano alla query filtrata.
1. Eseguire la seguente query GraphQL con `pageSize` impostato su due e `currentPage` impostato su uno:

   ```graphql
   query {
     customer {
       requisition_lists(
         pageSize: 2
         currentPage: 1
       ) {
         items {
           uid
           name
         }
         total_count
         page_info {
           current_page
           page_size
           total_pages
         }
       }
     }
   }
   ```

1. Esegui questa query GraphQL:

   ```graphql
   query {
     customer {
       requisition_lists(
         filter: { name: { match: "%ABC%" } }
         pageSize: 2
         currentPage: 1
       ) {
         items {
           uid
           name
         }
         total_count
         page_info {
           current_page
           page_size
           total_pages
         }
       }
     }
   }
   ```


<u>Risultati previsti</u>:

* La query `requisition_lists` restituisce `total_count` uguale al numero totale di elenchi di richieste di acquisto di proprietà del cliente, indipendentemente da `pageSize` e `currentPage`.
* I dati di impaginazione rimangono coerenti con il set di risultati corrispondente completo.

<u>Risultati effettivi</u>:

`total_count` restituisce solo il numero di elementi nella pagina corrente, ad esempio due anziché sei.
