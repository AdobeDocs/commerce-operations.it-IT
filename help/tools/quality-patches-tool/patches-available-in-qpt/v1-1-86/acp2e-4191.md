# ACP2E-4191: le richieste REST API entrano in loop infinito quando la cache di tipi e attributi EAV è disabilitata

La patch ACP2E-4191 risolve il problema in cui alcune richieste REST API entrano in un ciclo infinito quando la cache dei tipi e degli attributi EAV è disabilitata. Questa patch è disponibile quando è installato [[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) 1.1.86. L’ID della patch è ACP2E-4191. Questo problema è stato risolto in Adobe Commerce 2.4.9.

## Prodotti e versioni interessati

**La patch è stata creata per la versione di Adobe Commerce:**

* Adobe Commerce (tutti i metodi di implementazione) 2.4.7-p9, 2.4.8-p2

**Compatibile con le versioni di Adobe Commerce:**

* Adobe Commerce (tutti i metodi di implementazione) 2.4.5 - 2.4.8-p5

>[!NOTE]
>
>La patch potrebbe diventare applicabile ad altre versioni con le nuove versioni di [!DNL Quality Patches Tool]. Per verificare se la patch è compatibile con la versione di Adobe Commerce in uso, aggiornare il pacchetto `magento/quality-patches` alla versione più recente e verificare la compatibilità nella pagina [[!DNL Quality Patches Tool]: Cerca patch](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html?lang=it). Utilizza l’ID patch come parola chiave di ricerca per individuare la patch.

## Problema

Alcune richieste REST API entrano in un ciclo infinito quando la cache dei tipi e degli attributi EAV è disabilitata.

<u>Prerequisiti</u>:

Estensione Adobe Commerce [!DNL B2B].

<u>Passaggi da riprodurre</u>:

1. Crea un account cliente ed effettua l&#39;accesso a Storefront.
1. Aggiungi un prodotto al carrello e apri la pagina di pagamento.
1. Negli strumenti di sviluppo del browser, aprire la scheda Rete ed esaminare le richieste REST, ad esempio `rest/default/V1/carts/mine/estimate-shipping-methods`.
1. Disattiva la cache dei tipi e degli attributi EAV:

   ```
   bin/magento cache:disable eav
   ```

1. Aggiorna la pagina di pagamento ed esamina le stesse richieste REST.

<u>Risultati previsti</u>:

1. Le richieste REST di pagamento vengono completate senza immettere un ciclo infinito.

<u>Risultati effettivi</u>:

1. Le richieste REST non riescono e viene visualizzato un errore HTTP 500 perché il ciclo infinito raggiunge la dimensione dello stack di chiamate PHP o il limite di memoria.
