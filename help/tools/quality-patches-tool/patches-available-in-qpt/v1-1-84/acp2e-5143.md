# ACP2E-5143: la query GraphQL `route` esegue il rendering del contenuto della pagina CMS non richiesto

La patch ACP2E-5143 risolve il problema relativo al rendering dell&#39;intero contenuto della pagina CMS, inclusi widget Page Builder ed elenchi di prodotti, da parte della query GraphQL `route`, anche quando vengono richiesti solo i campi di routing URL, rallentando così la risoluzione degli URL. Questa patch è disponibile quando è installato [[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) 1.1.84. L’ID della patch è ACP2E-5143. Tieni presente che questo problema è pianificato per essere risolto in Adobe Commerce 2.4.10.

## Prodotti e versioni interessati

**La patch è stata creata per la versione di Adobe Commerce:**

* Adobe Commerce (tutti i metodi di implementazione) 2.4.7-p9

**Compatibile con le versioni di Adobe Commerce:**

* Adobe Commerce (tutti i metodi di implementazione) 2.4.4 - 2.4.7-p10

>[!NOTE]
>
>La patch potrebbe diventare applicabile ad altre versioni con le nuove versioni di [!DNL Quality Patches Tool]. Per verificare se la patch è compatibile con la versione di Adobe Commerce in uso, aggiornare il pacchetto `magento/quality-patches` alla versione più recente e verificare la compatibilità nella pagina [[!DNL Quality Patches Tool]: Cerca patch](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html). Utilizza l’ID patch come parola chiave di ricerca per individuare la patch.

## Problema

Problema in cui la query GraphQL `route` esegue il rendering dell&#39;intero contenuto della pagina CMS, inclusi i widget di Page Builder e gli elenchi di prodotti, anche quando sono richiesti solo i campi di indirizzamento URL, rallentando la risoluzione dell&#39;URL.

<u>Prerequisiti</u>:

Page Builder è installato.

<u>Passaggi da riprodurre</u>:

1. Vai a Amministratore > **[!UICONTROL Content]** > **[!UICONTROL Elements]** > **[!UICONTROL Pages]** e fai clic su **[!UICONTROL Add New Page]**.
1. Immettere i dettagli della pagina, impostare **[!UICONTROL Enable Page]** su **[!UICONTROL Yes]** e fare clic su **[!UICONTROL Edit with Page Builder]** nella sezione **[!UICONTROL Content]**. Espandere **[!UICONTROL Add Content]** nel pannello Page Builder e trascinare un segnaposto **[!UICONTROL Products]** nell&#39;area di visualizzazione, oppure inserire un widget di prodotto catalogo nel contenuto della pagina.
1. In Amministratore, vai a **[!UICONTROL Stores]** > **[!UICONTROL Settings]** > **[!UICONTROL Configuration]**. Nel pannello a sinistra in **[!UICONTROL General]**, scegli **[!UICONTROL Web]**, quindi espandi **[!UICONTROL Default Pages]**. Impostare **[!UICONTROL CMS Home Page]** sulla nuova pagina e fare clic su **[!UICONTROL Save Config]**.
1. Invia la seguente richiesta GraphQL:

   ```
   query ResolveURL($url: String!) {
     route(url: $url) {
       relative_url
       redirect_code
       type
       ... on CmsPage { identifier __typename }
       ... on ProductInterface { uid __typename }
       ... on CategoryInterface { uid __typename }
       __typename
     }
   }
   ```

1. Utilizza le seguenti variabili per la richiesta:

   ```
   { "url": "/" }
   ```

<u>Risultati previsti</u>:

La query `route` restituisce i metadati di routing e i campi discriminatori di tipo richiesti per la home page di CMS senza eseguirne il rendering completo del contenuto.

<u>Risultati effettivi</u>:

1. La query `route` esegue il rendering dell&#39;intero contenuto della home page di CMS anche se sono richiesti solo metadati di routing e campi discriminatori del tipo.
1. I widget di Page Builder caricano le raccolte di prodotti, aumentando il tempo di risposta e il numero di query di database per richiesta.
