# ACP2E-5122: gli errori del carrello GraphQL gestiti non vengono scritti correttamente nel registro eccezioni

La patch ACP2E-5122 risolve il problema per cui gli errori di richiesta del carrello GraphQL gestiti vengono scritti nel registro eccezioni come errori dell’applicazione. Questa patch è disponibile quando è installato [[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) 1.1.84. L’ID della patch è ACP2E-5122. Tieni presente che questo problema è pianificato per essere risolto in Adobe Commerce 2.4.10.

## Prodotti e versioni interessati

**La patch è stata creata per la versione di Adobe Commerce:**

* Adobe Commerce (tutti i metodi di implementazione) 2.4.8-p5

**Compatibile con le versioni di Adobe Commerce:**

* Adobe Commerce (tutti i metodi di implementazione) 2.4.4 - 2.4.9

>[!NOTE]
>
>La patch potrebbe diventare applicabile ad altre versioni con le nuove versioni di [!DNL Quality Patches Tool]. Per verificare se la patch è compatibile con la versione di Adobe Commerce in uso, aggiornare il pacchetto `magento/quality-patches` alla versione più recente e verificare la compatibilità nella pagina [[!DNL Quality Patches Tool]: Cerca patch](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html?lang=it). Utilizza l’ID patch come parola chiave di ricerca per individuare la patch.

## Problema

Gli errori di richiesta del carrello GraphQL gestiti vengono scritti nel registro eccezioni come errori dell’applicazione.

<u>Passaggi da riprodurre</u>:

1. Invia una mutazione di GraphQL `placeOrder` con un ID carrello mascherato non valido, scaduto o già eliminato, ad esempio questa mutazione:

   ```
       mutation {
           placeOrder(input: { cart_id: "test" }) {
               orderV2 {
                   id
                   number
               }
           }
       }
   ```

1. Controlla la risposta di GraphQL.
1. Controlla `var/log/exception.log` per l&#39;errore del carrello.

<u>Risultati previsti</u>:

1. La richiesta GraphQL restituisce un payload di errore gestito rivolto al client per il carrello non valido senza una risposta *HTTP 500*.
1. L&#39;*GraphQlNoThatEntityException* gestita non è stata scritta in `var/log/exception.log` e viene indirizzata a un canale di registro di gravità inferiore.

<u>Risultati effettivi</u>:

Ogni richiesta scrive l&#39;eccezione gestita in `var/log/exception.log` con gravità `report.ERROR`, causando una crescita illimitata del registro durante le richieste ripetute.
